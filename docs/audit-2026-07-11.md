# Ledger-vs-database audit — 2026-07-11

A full reconciliation of the migration **ledger** (everything committed
under `supabase/migrations/`) against the **live production database**,
run after the 2026-07-11 drift incidents (0034 phantom, 0045 anon-grant
outage — see [`incident-2026-07-11.md`](./incident-2026-07-11.md)). The
question it answers: *does prod actually equal the sum of the
migrations, or has it drifted?*

**Verdict: production conforms fully to the migration ledger.** The sole
delta is **0049** (written-not-applied by design — awaits the Phase 2b
email runbook). **0034** is confirmed as the only historical phantom,
and every 2026-07-11 repair (0052, the manual 0034-gap blocks, and 0053)
is verified in place.

---

## 1. Method

Deterministic replay + fingerprint diff, not eyeballing:

1. **Schema replay from zero.** Every migration in `supabase/migrations/`
   applied in order against an empty database, with `auth`, `storage`,
   and the Supabase roles (`anon`, `authenticated`, `service_role`)
   stubbed so the DDL runs standalone. This yields the *ledger's*
   canonical schema — what prod SHOULD be if it equals the sum of the
   migrations.
2. **Per-section fingerprints.** The replayed schema and the live schema
   are each reduced to per-section fingerprints, whitespace-normalized so
   cosmetic formatting can't create false diffs:
   - columns (name · type · nullability · default)
   - policies (name · cmd · roles · `USING` · `WITH CHECK`)
   - functions (signature · body, **whitespace-normalized**)
   - triggers (table · timing · event · function)
   - indexes (definition)
   - constraints (type · definition)
   - anon / authenticated **column grants**
   - realtime publication membership
3. **Capped roll-up hashes.** Each section's fingerprints are rolled up
   into a single capped hash so the whole section compares in one value
   (the "section roll"). Prod-roll vs replay-roll per section.
4. **Reconstruction proof for the function section.** The one section
   where a live hotfix / pending migration could legitimately differ was
   proven by reconstruction rather than a bare equality check:

   > **prod C-roll  ==  replay-minus-0049 C-roll**
   > `d1ae472d71e900818e013783c16b8347`

   i.e. the live function section equals the *ledger replayed with 0049
   removed* — which is exactly the expected state, since 0049 is the only
   written-not-applied migration. The match confirms prod = ledger − 0049,
   with no other function drift.
