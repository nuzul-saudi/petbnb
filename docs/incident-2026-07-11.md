# Incident / findings ledger — 2026-07-11

Six findings surfaced during the S10 golden-path E2E bring-up and the
concurrent founder onboarding walkthrough. Each is recorded with its
root cause and resolution so the decision trail survives. The first
true logged-out / robot client (the E2E) plus a fresh founder pass were
what exposed the set — every prior tester was authenticated and every
prior account was hand-driven, so none of these had been hit before.

---

## 1. Onboarding trap — default door stamps `role='owner'`, no switch

**Symptom:** a host account provisioned ahead of time was completed
through the `/name` screen and came out as an `owner`, with no way to
convert it to a host (0039 splits owner/host at the email level — same
email can't be both).

**Root cause:** the standard sign-in funnel
(`sign-in → verify → set-password → name → home`) always creates an
OWNER. Finishing a pre-provisioned account via `/name` runs that
default door and stamps `role='owner'`. There is no role switch (the
persona toggle was removed by 0039).

**Resolution:** docs guard added (README pre-passworded-account
warning) — deep-link would-be hosts to `/become-host/application`
instead of `/name`. The deeper product question (should the
email-level split stay absolute, or add an interstitial / role-add
path) is logged in `docs/post-pilot-backlog.md` as reopening Q1/0039 —
founder call required.

## 2. `complete-profile` dead end + bio wipe

**Symptom:** the post-approval host profile-completion screen
(`/become-host/complete-profile`) had no back affordance (a dead end),
and its photo/avatar detour destroyed the bio the host had already
typed.

**Root cause:** the screen navigated away to pick a picture without
persisting the in-progress bio, and shipped without a back control.

**Resolution:** folded into **Wave 1b TASK S4** (screen scaffold) —
the `<Screen>` wrapper gives it a back affordance, and the avatar
picker is inlined (or the draft persisted across the detour) so the
typed bio survives. Sanctioned small app change.

## 3–4. RTL photo carousels — dead arrows + desync + blank photos (×2)

**Symptom:** on the listing photo gallery and the listing-card
carousel, under RTL the arrows pointed/behaved wrong, the index
desynced from the visible photo, and some photos rendered blank.

**Root cause:** paging math assumed LTR geometry; a flex row under RTL
right-aligns, so the transform/scroll direction was inverted.

**Resolution:** shipped in the consolidated 3-part brief (commit
`cc654f8`) — pure RTL paging math in `src/lib/carousel-paging.ts`
(vitest-pinned both directions), a shared `CarouselArrow`, and
RTL-aware `PhotoGallery` / `ListingPhotoCarousel` / `PhotoLightbox`.
Discipline rule recorded in `docs/batch-decisions.md` (RTL carousel
paging).

## 5. `promote_listing_draft` 42703 drift chain

**Symptom:** promoting a host's listing draft threw `42703 column does
not exist`.

**Root cause:** migration **0034** (`listing_drafts.accepts_species`
+ related columns) was **wholly unapplied** in prod (see finding 6), so
`listing_drafts` lacked columns the promote RPC and the draft snapshot
referenced.

**Resolution:** migration **0052** repairs the prod drift (idempotent
`add column if not exists` + constraint re-add + drift audit), and
`src/lib/listing-draft-snapshot.ts` builds a faithful draft snapshot
that always carries `accepts_species`. Belt-and-braces coalesce-
hardening of the promote RPC for any future sparse draft is logged in
`docs/post-pilot-backlog.md`.

## 6. Apply-log drift — 0034 wholly unapplied, 0045 missing role-grant

**Symptom (a):** 0034 was recorded as applied but was not — the direct
cause of finding 5's 42703.

**Symptom (b):** the entire public listings feed was invisible to
logged-out clients in prod. 0045 added `host.role='host'` to the
anon-facing listings/profiles policy predicates but never extended
0037's column-level grant to include `role`; policy subqueries run with
CALLER privileges, so anon's missing SELECT on `profiles.role` failed
the whole policy as a table-level `42501 permission denied for table
profiles`. It went unseen for weeks because every human tester was
authenticated — the S10 E2E robot was the first true anon client.

**Resolution:** migration **0053** codifies the live hotfix
(`grant select (role) on public.profiles to anon`) + revokes anon's
inert default write grants; `docs/migration-apply-log.md` corrected
(0034 marked never-fully-applied; hotfix + 0052 recorded); the
grant-follows-predicate + editor-as-anon-probe discipline rules are
locked in `docs/batch-decisions.md`. The `is_visible_host` SECURITY
DEFINER helper that would retire this whole failure class is parked in
`docs/post-pilot-backlog.md`.
